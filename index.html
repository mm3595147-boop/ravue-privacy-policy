1. About this integration

Ravue is an experimental, non-commercial test integration with the Meta WhatsApp Business Cloud API. It uses a Meta-provided test phone number, and it is used only with test recipients the operator has added for testing. It is not advertised or offered to the public, and it does not serve customers.

Ravue is operated by Mahmoud Mansour, an independent developer. In the Meta developer dashboard, this integration's app is named “Commerce Messaging Lab”.

The integration runs only during short, manual testing sessions on the operator's own computer. When it is not running, it receives nothing.

2. What the integration does

  • It receives webhook notifications that Meta sends when a test recipient sends a message to the test number, and when the delivery status of a message changes (sent, delivered, read or failed).
  • It verifies that each notification really came from Meta, checks that it belongs to our test phone number, and writes a minimal technical log entry.
  • It does not send WhatsApp messages, does not reply automatically, and does not use WhatsApp data for marketing, advertising, profiling or analytics.

3. Information we receive

Notifications sent by Meta may contain:

  • the sender's or recipient's WhatsApp phone number and the sender's profile name;
  • message content (for example text), or details about media such as images;
  • message identifiers, timestamps and delivery status;
  • conversation and pricing information provided by Meta;
  • technical error codes and error descriptions provided by Meta.

4. How we process it — no persistent message storage

  • Signature check before reading the content. When a notification arrives, its raw body (limited to 1 MB) is received into memory first. We then check its cryptographic signature against those exact raw bytes. The content is parsed and read only after the signature has been verified. Requests without a valid signature are rejected and discarded without being parsed. Compressed request bodies are rejected without being decompressed.
  • In memory only. Verified notifications are processed in memory while the request is being handled. Phone numbers, names, message content and media details are not written to any database or file, and they are discarded once the request has been handled.
  • Other phone numbers ignored. Notifications that do not belong to our test phone number are ignored, and none of their details are logged.
  • Duplicate protection. To avoid processing the same notification twice, a one-way hash of each message identifier is kept in memory only for about 10 minutes. It is deleted automatically, and it is also lost whenever the program stops.
  • Technical logs only. The program writes log lines to the terminal of the operator's computer. These lines contain only non-personal technical fields: a timestamp, the event type (for example “message” or “status”), the message type (for example “text”), the delivery status, numeric error codes, a short reason code, and a random request identifier generated locally. Logs never contain phone numbers, names, message content, message identifiers (raw or hashed), error descriptions, or credentials.
  • Terminal output. The program does not write log files itself. However, the local development environment (for example terminal history, scrollback, or the output panels of development tools) may keep a copy of this terminal output on the operator's computer. Because the logs contain no personal data, any such copy contains no personal data either.
  • There is no database. This page and the integration use no cookies or trackers. We do not sell, rent or share personal information.

5. Service providers

  • Meta Platforms (WhatsApp Business Cloud API) delivers the notifications. Meta processes WhatsApp data under its own terms and policies, including the WhatsApp Privacy Policy.
  • Cloudflare provides a temporary secure tunnel during testing sessions only. Notifications pass through Cloudflare's network in transit. Cloudflare decrypts HTTPS traffic at its network edge before forwarding it through an encrypted tunnel to the operator's computer. The tunnel is closed after each session. See the Cloudflare Privacy Policy.
  • GitHub Pages is the planned hosting provider for this policy page. GitHub may log technical information about visitors, such as IP addresses. See the GitHub General Privacy Statement.

6. Security

  • Every incoming notification must carry a valid HMAC-SHA256 signature from Meta. Unsigned or altered requests are rejected before their content is parsed.
  • The program listens only on the operator's own computer (127.0.0.1). It can be reached from the internet only through the temporary tunnel, and only while a test is running.
  • Credentials are kept in a local configuration file that is excluded from source control. This integration does not store a WhatsApp access token.
  • Request size limits and strict input validation are enforced. Error details are never returned to the sender or written to logs.

No method of transmission or processing is completely secure, but we limit the data we handle to what this test requires.

Technical logs (no personal data) Shown in the local terminal. A copy may remain in the local development environment on the operator's computer.

8. Data deletion

We do not store message content, phone numbers or names, so normally this integration holds no personal data about you to delete.

If you were a test recipient and want to ask about your data or request deletion, email ravuesupport@gmail.com with the subject “Data deletion request”. We will reply within 30 days. Please do not include message contents or other sensitive details in your email.

You can delete messages or chats in WhatsApp at any time. Data held by Meta (WhatsApp) is managed under Meta's own policies and tools.

9. Children

This integration is not directed at children. It is used only with the operator's designated test recipients.
